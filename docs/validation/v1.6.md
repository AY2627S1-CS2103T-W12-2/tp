## Packaged application checks

An isolated JavaFX harness loads production classes from the candidate JAR and submits real
command-field events. Its 72 checks cover command acceptance/rejection, the v1.6 version,
meeting missing-index hints, plain/typed empty-search feedback, invalid edit indexes,
retained viewed contacts after an edit hides them, omitted empty feedback fields,
legacy JSON, meeting updates/clears/date and text validation, photo attach/replace/clear,
undo/redo, retained images, traversal/missing-photo errors and model/disk equality.

A separate Java process confirms that the saved meeting name/date/role and relative photo
reference reload. A storage probe creates two independent copies and confirms that each of
three stale-save attempts reports a conflict, rolls back its model and leaves the newer data
unchanged.

The executable entry point was launched with `java -ea -jar larperboard.jar` in a clean writable
folder. Its log reports `Starting LarperBoard v1.6` and `Starting UI...`. That isolated process was
terminated after observation; this is not a manual native interaction sign-off.

Help and delayed exit were also exercised while the contact data path was blocked by a directory.
Missing referenced images produced the expected placeholder. Fictional sample contacts were used.

## Publication checklist

- Review the release-preparation PR and its remote Java CI and Documentation results.
  Local test success does not establish remote CI success.
- Check the exact merged candidate on the intended native platforms, display scaling and
  physical input paths; record any untested environments explicitly.
- Confirm member portfolios/authorship and final release notes with the team.
- Rebuild the merged commit and repeat artifact verification. Record its commit and checksum.
- Publish the verified tag/JAR and matching checksum, notes and verification record.
- Update the README and landing-page published-release links to v1.6 after publication.
- Download the uploaded JAR and verify its checksum; check the deployed guide/report links.

Local build, UI, restart, storage and executable-launch evidence is retained in
`_temp/v1.6-preparation/`. No native platform sign-off or public release is implied by this record.
