## Packaged UI and restart smoke

A clean writable folder runs `java -ea -jar larperboard.jar`. Its log reports
`Starting LarperBoard v1.5` and `Starting UI...`; the isolated launch process is then stopped.
This checks the executable entry point; it is not claimed as a manual native interaction pass.

A separate harness uses `MainApp` from the same JAR and submits real command-field events:

- Legacy JSON without meeting/photo fields, partial meeting updates, clear/date errors, length bounds,
  and undo/redo pass.
- PNG photo attach/replace/clear, history chains, retained assets, traversal/missing-source errors,
  model/file equality and missing-image placeholder pass. The unit suite covers additional image
  formats, dimensions, size limits, unsafe references and parser errors.
- Help and delayed exit work with the contact data path blocked by a directory.
- A separate Java process reloads the saved meeting date/event/role and relative photo reference.

The five new v1.5 images in `docs/images/` are actual JavaFX snapshots using fictional contacts.
1280×720 scenes and simulated 150% constrained layouts were visually inspected. The latter uses
853⅓×480 logical pixels rendered at 1.5×; detail scrolling remains available. This is not native
OS display scaling or Windows/Linux manual sign-off.
