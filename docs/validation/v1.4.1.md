## Packaged-code smoke checks

113 independent checks pass against the release JAR's production classes with `java -ea`.
They cover activity timestamps, strict date validation, Singapore midnight/leap boundaries,
legacy and malformed JSON, persistence, no-ops, due ordering, zero results, plain/typed search,
unsupported prefixes, groups/stars, active filter feedback, displayed indexes, selection
retention, supported sorts, removal of `reset`, 50-entry history limits and later-view restoration.

A separate smoke harness uses `MainApp` from the same JAR and submits commands through the
real JavaFX command field in a fresh writable folder. It checks:

1. Old JSON containing only a name loads with absent meeting/photo fields.
2. Partial meeting updates, clear, undo/redo, valid leap dates, invalid dates and the 80/81-unit
   text boundary behave as documented; rejected commands leave the data unchanged.
3. Photo attach/replace/clear and a three-step undo/redo chain restore saved relative references
   and retain imported assets. Traversal and missing source report the exact documented errors.
4. Empty event searches and `list` restore the expected results and displayed indexes.
5. Tags, stars, notes, follow-ups and retained selection coexist with meeting/photo changes.
6. Missing managed photos show a placeholder and logged warning while data remains loadable.
7. With a directory deliberately blocking the contact-file path, `help` opens and `exit`
   closes the window successfully. The saved data is restored afterward in the disposable folder.
8. A separate Java process reloads the saved contact, meeting/date/role and relative photo reference.

The JAR also launches through its real `java -ea -jar` entry point in a separate clean folder;
its log reports `Starting LarperBoard v1.4.1` and successful UI initialization.
Native desktop-control attachment timed out, so that launch is not claimed as a manual native
end-to-end interaction pass.

## Layout evidence and remaining limits

The UG/README/landing-page images are real JavaFX scene snapshots from packaged code using
fictional contacts and a generated sample image. They show the detail-only 160×120 photo,
coloured tags with overflow, retained selection and active filter heading at 1280×720.
The 150% snapshots constrain the scene to 853⅓×480 logical pixels and render at 1.5×.
Those screenshots were visually inspected; vertical detail scrolling remains available.
This is simulated scaling, not a native Windows/Linux/macOS display-setting verification.

The pre-release source baseline had successful macOS/Windows/Linux Java CI at
[run 40692999585](https://github.com/AY2627S1-CS2103T-W12-2/tp/actions/runs/40692999585).
Java CI was manually disabled when the release PR was opened. The existing workflow was
re-enabled for release verification. The [release PR #210](https://github.com/AY2627S1-CS2103T-W12-2/tp/pull/210)
must pass Java CI and the documentation build before it is merged/published.
Post-merge workflows and the downloaded release checksum are checked separately at publication.

Known meeting Unicode and result-wording limitations, deferred sorts/filter combinations and
safe upgrade instructions are recorded in the [release notes](../releases/v1.4.1.html).
The v1.5 freeze check remains separate under #125.
