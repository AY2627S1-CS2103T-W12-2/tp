This is a draft for the upcoming release. The published download remains v1.4 until the
release owner publishes v1.5. This branch still reports `v1.4` at startup.

## Changes since v1.4

- Meeting event and role text now accept up to 80 Unicode code points, so a single emoji such
  as `😀` counts once. Commands and manually edited JSON use the same bound.
- The event preview on a contact card keeps whole Unicode characters when truncating to
  32 code points, including the ellipsis. The detail panel retains the full text.
- Refresh the meeting/photo screenshots and document the verified behavior and pending
  integration checks for [#124](https://github.com/AY2627S1-CS2103T-W12-2/tp/issues/124).

## Data and photo compatibility

Older contacts without `meeting` or `photoPath` still load. Meeting fields remain optional;
invalid present dates or text reject loading with a field-specific error in the log.
A missing, corrupt, unreadable, or unsafe photo produces a placeholder and logged warning
without preventing contact data from loading.

Photo sources must be PNG/JPEG files inside the folder containing the JAR. Absolute paths,
parent traversal and symlink escapes are rejected. Limits remain 5 MiB and 4096×4096 pixels.
Accepted files are copied to app-managed `photos/` with generated names, and JSON stores an
editable relative reference. Attach/replace/clear, delete and clear never automatically delete
imported images. Unused files may remain because undo/redo can restore earlier references.
Undo/redo and command recall remain session-only.

Back up `data/addressbook.json`, `preferences.json`, and the JAR-folder `photos/` before
upgrading or editing data. JSON and preferences use the working folder; photos use the JAR
folder. Running from the JAR folder keeps them together. Transfer the managed images with
contacts, and keep any images needed by the current session's history.
