**Preparation status: this candidate has not been published as a release.** It is based on
merged `master` at `23114c58`, plus the version and documentation changes in this release PR.
It excludes closed, unmerged PR #261 and #181. See the [verification record](../validation/v1.5.html).

## Changes since v1.4.1

- Accept accented and non-English names, combining marks, hyphens, and straight or curly
  apostrophes. Compose equivalent accents consistently when adding, editing, loading JSON,
  checking duplicates, and searching names. The 50-character limit counts Unicode code points
  after NFC normalization; it does not count extended grapheme clusters.
- Accept command words in any letter case. Prefixes such as `n/` remain case-sensitive.
- Keep the active filter when adding a contact, and explain when the new contact is hidden.
  Preserve the viewed contact when a different contact is edited out of a filtered list.
- Explain malformed and spaced search prefixes, invalid indexes, meeting/photo syntax, and
  duplicate contacts more clearly. Use LarperBoard/contact wording in the reviewed feedback.
- Redact personal note/meeting search arguments from logs, including rejected uppercase and
  spaced forms. This does not promise that names, phone numbers, or all commands are redacted.
- Prevent a stale open copy from silently overwriting changes saved by another copy. Saves
  use a companion lock and detect changes to the loaded data file; reopen to load the newer
  file before retrying. A busy save asks the user to retry later. This does not merge data.
- Close Help when the main window exits. The `exit` command displays its result for about
  one second before closing. `help` and `exit` remain available after contact-save failures.
- Refresh the guides, repository code links, screenshots, and release verification evidence.

## Run and upgrade

Use Java 25 with JavaFX as described in the [quick start](../UserGuide.html#quick-start).
For this candidate, build with `./gradlew shadowJar`, copy `build/libs/larperboard.jar` into
an empty writable folder, and run `java -ea -jar larperboard.jar`.
Published builds, once available, are on the [releases page](https://github.com/AY2627S1-CS2103T-W12-2/tp/releases).

Before replacing a previous JAR, close all copies and back up `data/addressbook.json`,
`preferences.json`, and the JAR-folder `photos/`. JSON/preferences are relative to the working
folder; managed photos are relative to the JAR folder. Launching beside the JAR keeps these
together. Keep `photos/` when moving contacts. The companion `addressbook.json.lock` may remain;
leave it in place. Undo/redo and command recall are session-only and reset on restart.

PNG/JPEG imports remain limited to 5 MiB and 4096×4096 pixels. Missing referenced images show
a placeholder and log a warning. Imported assets are retained because history can restore them.
Back up before editing JSON: malformed data starts an empty list, and later successful commands
can overwrite that file. `help` and `exit` preserve it.

## Known limitations and release gates

- Typed name search still differs from plain search for some Unicode case variants. For example,
  after adding `ΟΣ`, `find οσ` matches but `find n/οσ` does not. Use plain full-word name search
  as a workaround. This was reported on PR #260 and remains in the merged source.
- Meeting event/role length counts UTF-16 code units, and card truncation can split an emoji.
  PR #181 was closed without merging. No Unicode meeting fix is claimed in this candidate.
- Existing supported sort/filter behavior is unchanged; see the User Guide. No additional
  sort or combined-filter functionality is introduced by this release preparation.
- Native OS 150% display scaling and multi-platform manual UI sign-off remain unverified.
  Screenshots use actual JavaFX scenes at 1280×720 and simulated 150% constrained layout.
- The candidate is not a published beta. Review the release PR and CI, confirm member authorship,
  then test the exact merged commit before tagging and uploading the JAR and `SHA256SUMS`.
  Download the published artifact again and verify its SHA-256 before announcing it.
