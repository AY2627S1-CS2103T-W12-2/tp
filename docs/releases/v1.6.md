## Changes since v1.5

- Keep the contact-card tag row on one line, with a stable `+N` overflow indicator when
  selecting or deselecting a card (#275, #284).
- Explain that a plain `find` searches names only when it returns no matches, with examples
  for tag, note and event searches. Typed searches keep their existing feedback (#278, #280).
- Show event, date and role options when `meeting` is missing a contact index (#277, #281).
- Report an invalid `edit` index consistently with the other indexed commands (#279, #283).
- Keep the viewed contact visible in the detail panel when an edit, meeting update, follow-up
  update or star change hides it from the filtered list. Its updated details remain visible;
  displayed indexes still refer only to the current list (#286, #288).
- Omit empty phone, email and tag fields from contact feedback messages (#287, #289).
- Correct manual-test instructions, update website details, fill team documentation and
  acknowledge individual AI use. Archive the assigned notes/stars/recall/help/exit beta-test
  results and evidence (#273, #274, #276, #282, #285, #290, #291).

## Run and upgrade

Use Java 25 with JavaFX as described in the [quick start](https://ay2627s1-cs2103t-w12-2.github.io/tp/UserGuide.html#quick-start).
Build from source with `./gradlew shadowJar`. Put `build/libs/larperboard.jar` in a writable
folder, open a terminal in that folder and run `java -ea -jar larperboard.jar`.

Close every running copy before upgrading. Back up `data/addressbook.json`, `preferences.json`
and the JAR-folder `photos/` directory. v1.6 retains the v1.5 JSON format and storage paths:
contact data/preferences are relative to the working folder, while managed photos are relative
to the JAR folder. Launch from the JAR folder to keep them together. Keep the photo directory
when moving contacts. The companion `addressbook.json.lock` may remain in place.

Undo/redo and command recall are session-only. PNG/JPEG imports remain limited to 5 MiB and
4096×4096 pixels. Missing referenced photos show a placeholder; imported assets remain available
for undo/redo. Malformed contact data starts an empty list, and a subsequent successful command
can overwrite the file; `help` and `exit` preserve it. Always back up before editing JSON.

Keep the release JAR beside its `SHA256SUMS`. Verify it with `shasum -a 256 -c SHA256SUMS`
on macOS or `sha256sum -c SHA256SUMS` on Linux. On Windows, compare
`Get-FileHash .\larperboard.jar -Algorithm SHA256` with the checksum file.

## Known limitations

- Typed name search can differ from plain search for Unicode case variants. For example,
  `find οσ` matches a contact named `ΟΣ`, while `find n/οσ` does not. Use plain name search
  for this case. No typed-search Unicode fix is included in this release.
- Meeting event/role lengths count UTF-16 code units, and event truncation on cards can split
  an emoji. The previously closed, unmerged meeting Unicode work is not part of v1.6.
- Supported sorts remain `sort added`, `sort edited` and `sort viewed`. Separate filters replace
  each other; combined filters and additional sort commands are not introduced by v1.6.
- This release's packaged UI checks use macOS and JavaFX events. Simulated 150% constrained
  layouts are not native OS scaling. Windows/Linux and native input/scaling sign-off for the
  exact v1.6 artifact remain unverified, not inferred from the v1.5 beta reports.
