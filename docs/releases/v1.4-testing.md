Use a separate writable folder for testing so your real contacts remain safe.
Download `larperboard.jar` from the [v1.4 release](https://github.com/AY2627S1-CS2103T-W12-2/tp/releases/tag/v1.4)
and use Java 25 with the JavaFX setup described in the [User Guide](../UserGuide.html#quick-start).
The release includes `SHA256SUMS.txt` if you want to verify the download.

## Set up test data

Open a terminal in the folder containing the JAR and run `java -jar larperboard.jar`.
The following walkthrough **deletes the contacts in this test folder**. Run each command separately.

```text
clear
add n/Aisha Rahman p/98765432 e/aisha@example.com l/aisha-rahman t/frontend t/react
add n/Ben Tan p/87654321 t/backend
note 1 nt/Met at the AI track
meeting 1 ev/Hack Singapore md/2026-10-20 r/Mentor
star 1
followup 1 d/2020-01-01
view 1
```

Expect two contacts. Aisha's details show the note, event, date, role, star, and follow-up date.
The old follow-up date should have an overdue cue. Data is saved after successful commands.

## Search, grouping, and displayed indexes

Run each row's commands in order. A semicolon below separates commands to submit individually;
it is not part of LarperBoard syntax.

| Commands | Expected result |
| --- | --- |
| `find Aisha` | Only Aisha. |
| `find n/Aisha t/react nt/AI ev/Singapore` | Only Aisha: fields combine with AND. |
| `find n/Aisha n/Ben` | Both contacts: repeated name terms use OR. |
| `find noSuchContact` | A valid empty result. |
| `group t/backend`; `view 1` | Ben appears in the detail panel; index 1 means the first displayed contact. |
| `filter starred` | Aisha appears. This replaces the previous group filter. |
| `filter starred off` | Both contacts appear. |
| `due` | Only Aisha, with the earlier follow-up date. |
| `list`; `sort added`; `sort edited`; `sort viewed` | Each supported order is shown above the list. Equal times retain original order. |
| `view 1` | Opens the currently displayed first contact; under `sort viewed` it may move. |
| `reset` | Both contacts in original order. |

Separate filters do not combine in v1.4. `sort name` and `sort starred` are deferred in #128
and should show usage errors. Use `reset` before the following sections.

## Photos and saved data

Place any valid PNG named `portrait.png` and JPEG named `replacement.jpg` beside the JAR.
Use real image files rather than renaming another file type.

```text
photo 1 f/portrait.png
view 1
photo 1 f/replacement.jpg
photo 1 clear
undo
redo
undo
```

Expect a list thumbnail and an aspect-preserving detail photo after attachment/replacement.
Clear removes the reference; undo restores it; redo clears it again. The final undo restores the JPEG.
Imported files remain in `photos/` for history; unused copies may remain.

Close and restart the app from the same folder, then run `view 1`. Contact details and the photo
should remain. Undo/redo and command recall start empty in the new session.
Back up the test folder before editing JSON. Optional fields missing from old files should use their
empty defaults; malformed present fields should produce a warning and an empty startup list.
Do not run a successful command after a malformed-data test until you have restored the backup,
because successful commands save the current list.

For a missing-image test, close the app, move one referenced imported photo outside `photos/`,
restart and view its contact. Expect a placeholder and a log warning, with other contacts usable.
Restore the file afterwards. Absolute paths, `..` traversal, escaped symlinks, invalid image content,
files over 5 MiB, and dimensions over 4096×4096 must be rejected when importing.
See the [photo errors](../UserGuide.html#contact-photos-photo) for exact messages.

## Editing, clear forms, and undo/redo

After restarting, run `list` and then the following commands individually:

```text
edit 2 n/Ben Tan p/87654322
undo
redo
tag 2 t/mentor
note 1 clear
meeting 1 clear date
meeting 1 clear
followup 1 clear
unstar 1
photo 1 clear
delete 2
undo
```

Ben's phone should change, revert, then change again. Clearing fields affects only the named fields;
clearing meeting context removes all its fields. Undo restores deleted Ben. The original phone shown
above belongs to disposable test data. Real changes enter the 50-step undo history; no-op and failed
commands do not. Undo/redo is independent of command-text recall.

## Keyboard and layout checks

- Focus the command field. Submit `list`, then an invalid command such as `bad-command`.
  Type an unfinished draft; Up recalls the failed command and Down restores the draft.
- Submit `list` twice in succession, then `reset`. Up should recall `reset`, then a single `list` entry.
  Neither command clears earlier command recall. Up stops at the oldest retained entry; Down returns
  to the saved draft. The limit is 50 submitted commands, separate from 50 undo steps.
- Try Up/Down in the contact list and other controls. They should keep their normal behavior.
- Check a 1280×720 window, a long note (up to 1000 characters), and event/role strings up to 80 characters.
  Verify the event cue, star, overdue cue, and scrolling detail panel. Photos should not stretch.
- Check native 150% display scaling if available and record the OS/display settings. Existing images
  labeled simulated 150% are layout evidence, not confirmation of native OS scaling.
- Open Help and verify its User Guide link. The app's contact workflow does not require network access;
  opening the online guide does.
